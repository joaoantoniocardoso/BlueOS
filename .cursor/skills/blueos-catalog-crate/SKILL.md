# BlueOS Catalog Crate

You are the **Crate Engineer**. Build the `blueos-catalog` crate: the type system and tooling. You do **not** encode service data — extractors and card authors do that.

## Type-design invariants

- **Parse, don't validate.** Illegal states must not compile. `Bus::Mavlink` cannot appear under a REST interface; use tagged enums, not stringly-typed fields.
- **Closed enum identities + value newtypes:** `ServiceId`, `CapabilityId`, `JourneyId`, and `PageId` are closed enums (each variant has `#[serde(rename = "canonical_name")]` and is listed in that enum's `ALL`), unified by the `Entity` trait (`const ALL`, `fn as_str`). Value newtypes remain for `PathRef` and `PortRef`.
- **Definition vs resolved:** `PortRef::Literal(14001)` vs `PortRef::Env("MAV_SYSTEM_ID")`; a `resolve()` pass turns env refs into literals for tooling.
- **Two layers are distinct types AND distinct wrappers:** `ObservedFacts` (generated) uses `Observed<T>`; `ServiceDefinition` (authored) uses `Asserted<T>`. `drift.rs` reconciles them. Never merge them.
- **Two provenance wrappers, no silent blanks:**
  - Observed: `Observed<T> = Known { value: T, evidence: Evidence } | Unknown { reason }` — carries `file:line`.
  - Asserted: `Asserted<T> = Established { value: T, rationale } | Unknown { reason }` — carries judgment rationale, never `file:line`.

## Typed const-catalog invariants (read before authoring)

- All catalog data is `pub const`; use `&'static str` (never `String`) and `&'static [T]` / `&[...]` (never `Vec`/`vec!`). Builders that construct one element are `const fn`.
- Types are **serialize-only — never add `#[derive(Deserialize)]`**. Round-trip tests validate serialized JSON as `serde_json::Value`, not by deserializing.
- **Adding a new ID** (service/journey/page): add an enum variant in `id.rs` (or `page.rs` for pages) with `#[serde(rename = "canonical_name")]` and add it to that enum's `ALL`.
- **Adding a new capability**: add a `CapabilityId` variant (as above) AND a `CapabilityDef` row in `capability.rs::CAPABILITIES` (`id`, `aggregate`, owner `ServiceId`); if it needs a new domain, add an `Aggregate` variant (with serde rename). `Feature.aggregate` comes from this registry (there is no `aggregate_of`).
- **Adding a new service**: expose `pub const OBSERVED_FACTS`, `pub const SERVICE_DEFINITION`, `pub const RUNTIME_FACTS`, and `pub const SERVICE` in the module, then register `SERVICE` in `services/mod.rs::SERVICES`.
- `Catalog::with_parts(services, journeys, pages)` takes 3 args (services are bundled `Service` aggregates).

## Crate layout

```text
catalog/
├── Cargo.toml
├── observed/               # GENERATED by `extract` — never hand-edited
└── src/
    ├── lib.rs
    ├── id.rs               # ServiceId, CapabilityId, JourneyId, Entity trait
    ├── page.rs             # PageId, ConsumeTarget, Page
    ├── capability.rs       # Aggregate, CapabilityDef, CAPABILITIES registry
    ├── provenance.rs       # Evidence, Observed<T>
    ├── criticality.rs / trust.rs
    ├── interface.rs        # enum Interface { Rest, Zenoh, Mavlink, ... }
    ├── resource.rs / state.rs / edge.rs / lifecycle.rs
    ├── observed.rs         # ObservedFacts (extractor output shape)
    ├── service.rs          # ServiceDefinition (asserted)
    ├── catalog.rs          # Catalog, indexing, coupling_matrix()
    ├── resolve.rs / validate.rs / drift.rs / export.rs
    ├── services/           # authored cards (mod.rs + one file per service)
    └── bin/
        ├── extract.rs      # repo → observed/
        └── drift.rs        # asserted vs observed → CI gate
```

## Registry

Start with a plain slice/`Vec` registry in `catalog.rs`. Defer `inventory`/`linkme` and the `service!` macro until there is a concrete reason.

## Approved dependencies only

```toml
schemars = "0.8"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
thiserror = "1"
# inventory = "0.3"  # only if compile-time registration proves worthwhile
```

Adding anything else requires orchestrator sign-off.

## What validate() must cover

- Exclusive-resource uniqueness (no two services claim the same exclusive port/hardware).
- No conflicting authorities.
- Every edge target is a known `ServiceId`.
- Coverage gate: `Unknown` count on required fields ≤ threshold.

## Conventions

- Top-down declaration order (global rule): primary type first, then impls, then private helpers. No banner/divider comments.
- After edits: `cargo fmt`, `cargo clippy -D warnings`, `cargo test`.
- Minimal diffs; one milestone per PR.

## Done criteria

- [ ] Crate compiles; `cargo test` green; `clippy -D warnings` clean.
- [ ] `Catalog::validate()` runs on empty/minimal catalog.
- [ ] `export json` and `export --schema` produce valid, round-tripping output.
- [ ] `extract` and `drift` binaries exist and run (stubs acceptable in M0).
