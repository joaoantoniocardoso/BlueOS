# blueos-api (frontend)

Framework-agnostic TypeScript client for the versioned BlueOS zenoh IDL API (D-08, D-14). It reuses the
existing websocket zenoh session at `/zenoh-api/` (`src/libs/zenoh`) and never opens a second session.

IDL types and `ros2msg` schema text come from `core/libs/idl/typescript/` (generated by `blueos-idl`).

## Key layout and encoding

Mirrors `core/libs/api/src/lib.rs` and `core/libs/api/README.md`:

| Helper | Zenoh key |
|---|---|
| `stateKey(service, name)` | `blueos/v1/<service>/state/<name>` |
| `commandKey(service, name)` | `blueos/v1/<service>/command/<name>` |
| `queryKey(service, name)` | `blueos/v1/<service>/query/<name>` |
| `jobsKey(service)` | `blueos/v1/<service>/jobs` |
| `settingsKey(service)` | `blueos/v1/<service>/settings` |
| `logKey(service)` | `blueos/v1/<service>/log` |
| `serviceLivelinessKey(service)` | `blueos/v1/services/<service>` |
| `infoQueryKey(service)` | `blueos/v1/<service>/query/info` |

Payloads are plain CDR bytes (no framing). Zenoh encoding is `cdrEncoding(schemaName)` ->
`application/cdr;<schema_name>` (for example `application/cdr;blueos_msgs/msg/CommandAck`).

Type hash attachment key: `blueos.type_hash` (`TYPE_HASH_ATTACHMENT_KEY`).

## Schema evolution (D-06)

Within a major version, `.msg` fields are append-only. New writers with extra trailing fields decode on
older readers (extra bytes are ignored). Old writers missing trailing fields are supported by zero-padding
short payloads before decode (see `decodeCdr` in `cdr.ts`). This matches the Rust `blueos-idl` policy for
strings and other trailing primitives; it is not a full ROS 2 XTypes implementation. Native ROS 2 nodes
without padding still fail on short payloads.

## Shared memory (D-09)

Large zenoh payloads may use host SHM when both peers support it. Kraken extensions need `IpcMode: host`
(or a bind-mount of `/dev/shm`) to participate; otherwise traffic falls back to TCP loopback silently.

## API

Core exports (`index.ts`):

- `decodeCdr` / `encodeCdr` -- CDR via `@foxglove/rosmsg` + `@foxglove/rosmsg2-serialization`
- `watchState(service, name, schemaName, onValue)` -- query then subscribe; re-queries on zenoh link up
- `sendCommand(service, name, requestSchema, request, timeoutMs?)` -- zenoh query, returns `CommandAck`
- `query(service, name, responseSchema, requestSchema?, request?, timeoutMs?)`
- `watchJobs`, `watchServiceAlive`, `getServiceInfo`, `watchLogs`
- Key helpers and schema name constants

Vue 2: import `blueosApiMixin` from `src/libs/blueos-api/vue2.ts`. Methods are prefixed with `blueos` and
subscriptions are cleared in `beforeDestroy`. For Vue 3, replace the mixin with a composable that calls the
same core functions; do not import Vue from the core library.

### Example (Vue 2)

```javascript
import { blueosApiMixin } from '@/libs/blueos-api/vue2'
import { SERVICE_INFO_SCHEMA } from '@/libs/blueos-api'

export default {
  mixins: [blueosApiMixin],
  data() {
    return { statusDetail: '' }
  },
  mounted() {
    this.blueosWatchState('example', 'status', 'blueos_msgs/msg/ServiceStatus', (status) => {
      this.statusDetail = status.detail
    })
  },
  methods: {
    async runCommand() {
      const ack = await this.blueosSendCommand(
        'example',
        'DoWork',
        'blueos_msgs/msg/SomeRequest',
        { /* fields */ },
      )
      if (ack.accepted) {
        console.info('job', ack.job_id)
      }
    },
  },
}
```
