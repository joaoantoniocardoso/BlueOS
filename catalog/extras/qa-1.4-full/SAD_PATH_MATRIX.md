# SAD_PATH_MATRIX — BlueOS 1.4-dev sad/bad-path coverage for every journey

**Scope:** all 101 `JourneyId::ALL` entries (100 registered in `Catalog::bootstrap()` + `deploy`, which has no journey module — see Contradictions).
**Strategy:** Part 1 Track A/B/C/D of `.cursor/plans/qa-1.4-dev-full-feature-test.md`. No new `JourneyId` is proposed here except the Track A shortlist, and those are only promoted **after** live capture.
**Status codes:** every `expected_status` in this file is either (a) read out of BlueOS source, (b) read out of a catalog `failure_modes` assertion, or (c) written `UNKNOWN_LIVE`. Nothing is guessed.

## Legend

| Field | Values |
|---|---|
| automatable | `Http` / `Frontend` / `Hardware` / `Manual` (from `derive_automatable`, verified against `journey_http --dry-run` = 81 Http) |
| sad classes | `B1` invalid input · `B2` confirm/gate · `B3` missing precondition · `B4` double-apply/idempotency · `B5` resource/limit · `B6` service-down · `B7` mid-flow disruption · `B8` offline · `B9` auth/pirate/advanced · `n/a` + reason |
| blast | `safe` (no state change) · `reversible` (state change with declared restore) · `disruptive` (drops a subsystem, recovers by itself or by restart) · `destructive` (needs reimage/flash/reboot to undo) |
| dut_affinity | `all` · `177-only` (play Pi, destructive OK) · `not-2.2` (never on the USB ROV) · `pixhawk-87` (Pixhawk1 contrast) · `navigator` (Navigator-only surface) · `rf-serial` (needs the single host radio, serialized) |
| Track A? | `yes` = promote to a wifi-style failure journey; `no` = stays a Track B probe or Track C ledger entry |

Probe ids (`NP-nn`) match `NEGATIVE_PROBES.md`. `FM:<service>/<id>` refers to a `failure_modes` id in `FAILURE_MODE_LEDGER.md`.

## Contradictions and source/catalog divergences found

1. **`JourneyId::Deploy` has no journey.** `JourneyId::ALL` has 101 entries; `Catalog::bootstrap()` registers 100. `deploy` exists only in `catalog/src/id.rs:1005,1110` plus test fixtures (`validate.rs:980`, `export.rs:188`). Any claim of "101 journeys covered" is off by one until this is resolved.
2. **Dead 400 branch in disk_usage.** `FM:disk_usage/invalid_or_missing_path` asserts "404 **or 400** for missing paths or paths outside `/`", but `FILESYSTEM_ROOT = Path("/")` (`disk_usage/main.py:27`) makes the `relative_to` check at `main.py:99` always succeed, so the 400 at `main.py:100-103` is unreachable. Expect 404 for every traversal attempt.
3. **`POST /commander/v1.0/set_time` is not actually gated.** `FM:commander/i_know_what_i_am_doing_rejected` and the journey precondition `confirm_dangerous_op` imply a gate, but `set_time` (`commander/main.py:72-84`) returns 200 "not updating" for any timestamp within 5 minutes of now, *before* delegating to the gated `command_host`. The 400 only appears for a far-off timestamp.
4. **kraken declared vs returned status.** `POST /kraken/v2.0/extension/` declares `HTTP_201_CREATED` (`extension.py:78`) and `POST /extension/{identifier}/{tag}/install` declares 201 (`extension.py:99`), but both return a `StreamingResponse`; the catalog's runtime-captured `expected_status` is 200. The catalog value is the correct live contract — the divergence is in the source annotation, and it should be noted rather than "fixed" in the catalog.
5. **`GET /wifi-manager/v1.0/disconnect` mutates.** A GET that changes association state, and whose idle response is 500. The catalog already special-cases it in two places (`mutating_smoke.rs:439-443`, `runner.rs:1571-1576`), which is correct but worth surfacing as a product API-shape finding.
6. **Pirate/advanced mode is not a backend gate.** Journeys such as `modify_bag_database`, `configure_host_dns`, and `set_network_interface_priority` carry `Software(PirateMode)`/`AdvancedMode` preconditions, but the corresponding services have no authorization check — NP-96 will show a plain 200 without the fixture. B9 probes must therefore assert "frontend-gated only", not 403.
7. **Three services have no HTTP error mapping at all** (`bridget`, `nmea_injector`, `cable_guy`): every B3/B4 probe against them is `UNKNOWN_LIVE` by construction, and `FM:nmea_injector/remove_nonexistent_socket` ("returns error") has no status to verify against. This is why those rows carry `UNKNOWN_LIVE` rather than an assumed 500.
